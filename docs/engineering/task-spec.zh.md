# task-spec: 为什么是这样设计的

[English](./task-spec.md) | 中文版

> 这篇是给**人**读的。[`SKILL.md`](../../skills/engineering/task-spec/SKILL.md) 是给 AI
> 的指令集。想知道「为什么有这五个阶段」读这篇；要用这个技能直接用 SKILL.md。

## 起点：模型有四个洞

一个 LLM 逐个 token 生成文本，每次挑统计上最可能的下一个词。这个机制带来四个洞：

1. **默认就是第一个念头。** 概率最高的续写就是第一个「想法」，然后它就照着跑。不会
   自然地去想别的可能，也不会问「这是不是真正的问题」。
2. **没有质量梯度。** 它朝「最可能」走，不朝「更好」走。它分不出哪个方向更深。
3. **分不清「看起来对」和「真的对」。** 一个看起来合理的错答案和一个正确答案，在统计
   形状上是同一个东西。
4. **不检查自己的工作。** 「做完了」等于「做好了」。没有外力逼它，它不会去抓矛盾、
   漏项。

前两条发生在**行动之前**，后两条发生在**行动之后**。这两类问题的性质不同，修法也
不同。

## 两类问题需要两种策略

**验证**是容易的那个。「产出是否符合规格？」是个客观问题，可以从外部强制：一份契
约、一份清单、一组证据就够了。但清单不是穷尽的：它只能问规格已经想到的事，而能显
出规格漏了什么的东西，只有改动本身。所以验证阶段除了逐条核对标准，还要把改动本身
走一遍。

**思考**是难的那个。「方向对不对？」「够不够好？」这些需要模型没有的东西：一个指向
「更好」的内在罗盘。模型指向「最可能」，永远指向不了「更好」。它不是因为懒才草率收
场，而是因为它分辨不出哪个方向更深。

人类的对应物是**态度**。一个真的想把事情做好的人，自然会去探索替代方案、质疑前提、
预判风险。模型没有等价物。它没法「想要」任何东西。

所以：**验证能用契约强制，思考只能用结构推。**

## 五个阶段各自的由来

| 阶段 | 它在补哪个洞 | 不做会怎样 |
|---|---|---|
| **探索** | 洞 1、2 | 抓住第一个念头就跑，从没考虑过别条路 |
| **定规** | — | 没有可对照的基准，「做好了」无从判断 |
| **挑战** | 洞 1、2 | 第一个方案直接进执行，缺陷在产出里才暴露 |
| **执行** | — | 没有「离开轨迹」这个概念，边做边漂移无从发现 |
| **审查** | 洞 3、4 | 「跑通了」就算完成，实际上没达标的部分被留下 |

## 为什么是「两层循环」而不是一条直线

单次通过的流程无法纠错。两个阶段的配置成环，让问题能在**代价最低的时候**被抓到：

- **内循环**（探索 → 定规 → 挑战）在动手前打磨方案。轻微缺陷退回定规，重大缺陷退回
  探索。改一段文字的成本远低于改已经写进产出的东西。
- **外循环**（执行 → 审查 → 探索）在动手后验证结果。审查不通过不是「打个补丁」，
  是回到探索重启一轮——因为审查失败通常意味着原先的理解就不够，而不是最后一步
  歪了。

这些状态之间的走向由本技能自己定：一条发现能由哪个阶段处理，就退回哪个阶段。一个关卡回合
内部怎么做——方案或结果怎么冻结、怎么切块、谁来判——不由本技能定。那部分来自
`adversarial-review-loop` 技能，两者为什么能拼在一起，后面有一节专门讲。

每一层循环都在缩小问题，同时累积一条可查的记录。

## 为什么 spec 必须是「契约束缚」而不是「参考方案」

这是整个设计里最容易被误解的一点。

如果 spec 只是一份参考计划，那么：

- 执行阶段可以「顺便」做点 plan 上没有的事 —— 范围就此悄悄膨胀；
- 审查阶段可以拿「感觉差不多」当通过 —— 洞 3 原样复发；
- 「不在 spec 里」失去意义，scope 不再是能画线的地方。

所以 task-spec 明确规定：**spec 是不可偏离的契约**。执行只能做 spec 里写了的，审查
只能对照 spec 里写明的验收标准判 PASS/FAIL。spec 里没有的 = 不在本次范围内。

这约束的是审查阶段**能判什么**，不是它**能看见什么**。它在验收标准之外看到的问题，照样要
报出来；只是那些问题回探索阶段去，由那里重新定范围，而不是在审查阶段就地判决。

这不是形式主义。它是让「从这个草率的执行中把它拽回来」这件事在机制上成为可能。

## 挑战和审查各跑一个「只判断回合」

自己审自己的东西，最可能的结果是放过它——洞 3 说的就是这个。所以两道关卡都交给
`adversarial-review-loop` 技能：挑战判方案，审查判结果。这个技能有两种模式。**完整回合**
走它的第 1–6 步——冻结对象、切块并行找问题、去重、逐条独立复核、修掉存活的问题、再审修
出来的东西。**只判断回合**走到第 4 步就停：回合内不修、也不再审，交回的是问题清单。
task-spec 用的是后一种。

循环技能提供的是一个回合的做法：一份每个发现者都读得到的冻结对象，一套互不重叠、又能
覆盖整个对象的切块，一场允许越过检查表、去问「这条改动本该一起动的地方漏了哪里」的搜索，
以及一个没有写这条发现、因此能诚实否掉它的复核者。这些全都出自一条纪律：**发现问题的人
和判断问题是否成立的人，不能是同一个。** 这就是洞 3，而且它比「把审查交给子代理」这句
老话更严格。换一个上下文，只是去掉了「这是我想出来的」这个先验，本身已经有帮助；这条
纪律还禁止发现者给自己的发现判分。

task-spec 保留的是循环技能故意不碰的那一半。挑战和审查里都不修，两个阶段只把复核后存活的
东西分派出去：挑战里的轻微发现退回定规，重大发现退回探索，审查里任何存活的发现都让任务回到
探索、开新一轮。这条分派规则不是循环技能的一步，它是 task-spec 自己两层循环的形状，SKILL.md
把它写成了一张状态表。

两者能拼在一起，是因为一个回合有两半，两半归不同的流程负责。挑战如果跑完整回合，循环技能
会自己动手修方案，task-spec 接着又把同一条发现退回定规或探索：修和再审各做两遍，两个上下文
同时改同一份方案，而且没有任何东西说明哪一份改动算数。只判断回合去掉了这份重复——关卡判定
什么成立，方案的归属阶段决定怎么办，下一个回合判新状态。收敛因此是在 task-spec 内循环的
各轮之间量的，不是在循环技能一个回合内部量的。

这种模式有两个特点，决定了分派实际拿到的是什么。一条发现会被判成四种——有效、部分有效、
无效、subsumed（它只是一个更大问题的症状）——问题清单只留活下来的：有效的按发现者写的
样子留下，部分有效和 subsumed 留下的是改写后的版本，无效的一条都不进清单。「无效」这个
判决仍然要求复核者拿出反证，因为反证正是这个判决的依据，但没有任何东西会照着它动，所以
反证不进清单。
另一件事是，「部分有效」交回的东西也变了：过去回的是**边界**，说明这条发现里哪一部分说过了头；
现在回的是**改写**——把这条发现重写到剩下的部分完全成立为止，从此以后这条发现就是改写后的
样子。边界只是告诉读的人这条发现哪里不对，拿到它的阶段还得自己算出正确的那一版；改写交出
的就是能直接照做的那一版。所以审查分派的一律是改写后的版本，从来不是原版，已经被判无效的
发现也不会再回到分派这一步。subsumed 的发现上报的是它的根，理由一样：只把症状退回定规或
探索，结果就是症状被就地补了一下。

## 为了让这件事成立，task-spec 加了两样东西

两样东西针对的是同一个问题：只判断回合是一道关卡，而只被告知「检查什么」的关卡，会把注意到
的一切都当作问题报上来。

**有意不做的清单。** 定规阶段写下这次改动有意不做什么、考虑过又否掉了哪些替代方案、哪些
细节有意留白——没有就写「none」。这份清单属于标准本身，不是标准之外的说明：挑战和审查把
它原样交给每个发现者。没有它，发现者分不出「有意留白」和「缺陷」，于是把每一处有意留白都
当成缺陷报上来；这些条目数量多，又个个都像明显的缺口，真正该报的问题反而被挤到一边。清单
在一个回合里还必须保持不变：中途改清单，就等于换掉了先前那些判决所依据的标准。

**冻结副本。** 挑战或审查的一个回合开始前，spec 文件就是这个回合的冻结副本。循环技能对冻结
对象的要求，它已经满足：它在工作区里，所以发现者读得到；它可以前后比对；它也可以回滚。
由此有两条规则。回合开始前记下这个文件的摘要，下一个回合前再核对一次——如果文件动过，而
这个技能自己的分派并没有动它，就说明这个回合是拿一份中途变过的对象判的，要重新冻结、把
这个回合重跑一遍。spec 因为上一轮改了它而变化是正常的：重新冻结，记下新的摘要。

## 局限（诚实版）

- **这只是补偿，不是让模型变好。** 它不能阻止模型默认走第一个念头，它只是让模型**绕
  不过**本该自己走的那些步骤。
- **不是万能的。** 它无法替代模型真正的判断力。spec 写得再细，也救不了错误的领域理解。
- **流程本身不产出质量。** 五个阶段全部走完、但每个阶段都在敷衍，结果依然是烂的。
  这条也一样适用于人做审查。
- **循环里贵的那一半，两道关卡都要付一遍。** 挑战和审查各自都要走冻结、切块、搜索、独立
  复核。只判断回合省下的是修完再审的那一半，而那一半 task-spec 本来也要通过自己的分派
  再走一遍。
- **开销是真的。** 小任务跳阶段（各阶段都有「琐碎任务」豁免），但非平凡任务不能省。
