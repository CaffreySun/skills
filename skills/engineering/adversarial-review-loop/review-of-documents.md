# 被审对象是「已发布文档」时的替换做法

> 只在被审对象**没有 diff**（是一份已发布文档本身）时读这份。主体流程照
> [`SKILL.md`](./SKILL.md) 走，这里只给四处需要换掉的做法。

被审对象**不是改动 diff**，而是一份已发布的方案 / 文档本身（工单正文、在线文档、规格书草稿、提案）时，分区审查 → 去重 → 复核三分类 → 下沉 → 收尾回归的主体流程完全照走，只把下面四处换成对应做法。

### 1. 固化对象（先做，否则审的是错的副本）

1. 把正文写到本地文件（如 `$S/.review-scratch/<name>-plan.md`，见 `SKILL.md` §5「落盘位置」），记录 `md5` 与字节数。
2. **与已发布副本逐字校验**：用该平台的读取命令取回正文（如 `gitee issue view <ident> --json=body --no-tui`、`lark-cli docs +fetch`），比对 `strip()` 后是否相等。**不等就别开审。**
3. 每轮修复前先写一份 `r<N>-before.md`，改完写 `r<N>-after.md`，并生成 `unified_diff` 存成 `r<N>-delta.diff`——**下一轮的被审对象就是这个 delta**，不是全文。

### 2. 四轴分区（按维度切，不按文件切）

| 轴 | 审什么 | 取证要求 |
|---|---|---|
| 事实准确性 | 方案对现状的**每条论断**能否被代码 / 规范证实 | 逐条判决，**不许抽样**（方案里最容易错的就是「全仓 N 处」「只有 M 类」这类计数与枚举） |
| 可行性与自洽 | 链路能否真跑通、参数够不够渲染、去重 / 幂等能否定义、与被引用规范的骨架与禁则是否相容 | 引被引用规范逐条对照 |
| 覆盖与遗漏 | 用领域全量底稿（如「人出手时刻 × 可观测产物」矩阵）逐行核对清单 | 找漏项 + 找**口径缺失**：谁收、一次事件发几条、命令类流程是否也发 |
| 边界、风险与落点 | 与既有架构 / 边界文档是否冲突、密钥与权限面、规范落点是否够、分期是否合理 | 专探「漏了哪条既有路径」 |

边界轴里最有价值的探针（实测每次都能出货）：

- 新入口 / 新字段是否沿用了既有的鉴权与隔离口径；
- 新配置列会不会被既有 `SELECT *` 类接口明文回吐（凭证泄漏）；
- 去重 / 幂等键会不会吞掉「同键的新一轮合法事件」；
- 声称「与 XX 同级」的改动，是否真的落到了 XX 的规范老家。

### 3. 修复回写与字节一致性校验

- 改本地文件（用 `SKILL.md` §7「只修经复核的项」里的断言式精确 `old→new` 替换）。
- 回写已发布对象：`gitee issue edit <ident> -b "$(cat file)"`（多行正文走文件，别拼 shell 字符串）。
- **每轮回写后必须再逐字校验一次**「已发布 == 本地」（同上面的 `md5` / `strip()` 比对），并做旧措辞残留 grep：旧数字、旧指针、被替换的措辞**全为 0**。
- 编号引用自检：抽出全文所有 `§N`，确认每个 N 都存在于章节集合。

### 4. 收敛与报告差异

- 终止判据与主体流程相同（某一轮 0 条有效发现 + 0 条部分有效）；本类对象的实测轨迹是 **9 → 9 → 2 → 0**：修复轮自带残留，前两轮各约 4 条「改一处漏一处」；**不要**在第一轮修完就收工。
- 报告除通用模板外，最终闭环证据必须给**原始输出**：`md5` + 已发布 == 本地 + 残留 grep + 引用自检。
